## 3. 新增能力速查（现在能做什么）

```text
/module-add   "sii"  <plugin|model slug>  <x格>  <y格>   → 新模块 id（可 undo）
/load-skipped ""                               → 上次 load 跳过的模块/线清单
/log-get      "ii"   <from>  <limit≤64>       → 进程内日志增量读
/cables-page  "ii"   <offset> <limit≤64>      → 分页读线
/module-copy  "hi"   <moduleId> <withCables>  → 复制模块
```

MCP 侧对应：`cardinal_add_module` / `cardinal_load_skipped` / `cardinal_log_get` / `cardinal_cables_page` / `cardinal_module_copy` / `cardinal_add_cable` / `cardinal_remove_cable` / `cardinal_move_module` / `cardinal_remove_module`。

## 4. 怎么跑 / 怎么验（可复现）

```bash
# 1) 源码树重放 + 端点校验（WSL）
cd ~/Cardinal && python3 /mnt/d/Cardinal/tools/osc_patch/replay_osc.py --verify
#    ⇒ 期望：端点数 33 / 33，✅ 校验通过

# 2) 编译 + 部署（WSL → Windows 盘）
cd ~/Cardinal && source deps/PawPaw/local.env win64 && cd src
make rack.a -j$(nproc) && make -C CardinalNative -j$(nproc)   # 动 Rack 层必须先 make rack.a
cp ~/Cardinal/bin/CardinalNative.exe /mnt/d/Cardinal/win64/CardinalNative.exe

# 3) 起真机（Windows 侧）：D:\Cardinal\win64\CardinalNative.exe
#    OSC 端口 2228 自动开；MCP 侧用 CARDINAL_IP=<WSL IP> 连
```

## 6. 已知坑速查（这轮踩的，别再踩）

| 坑 | 症状 | 正解 |
|---|---|---|
| **Cardinal 编译的是 `src/override/Engine.cpp`**，不是 Rack 原版 | 链接期 `undefined reference to rack::xxx` | 改 Rack 层前先 `ls src/override/`；判定：`nm -C src/rack.a \| grep 符号` |
| **typespec 必须与参数顺序一致** | 端点永远哑（liblo 不派发） | `"sii"` ≠ `"ssi"`；写完立刻用探针发一条真消息验 |
| **别在 OSC 侧调人类路径独有的 UI 动作** | 调 `loadTemplate()` 后 undo 就让 OSC 失联 | 手动执行只抄「引擎 + 容器 + 定位」三步 |
| **错误码语义别复用** | `err:E_NO_PLUGIN` 在既有约定里是「桥未就绪」 | 「slug 不存在」用 `err:E_NO_MODEL` |
| **探针自己的回包语义** | 同一份探针里 ask 返回列表还是元组？ | 先 dump 原始回包对齐语义，再写断言 |
| **自写 OSC 消息别手拼** | 地址段多一个 `\0` ⇒ 请求发不出去 | 照抄已验证的构造器（pad 到 4 字节） |
| **WINE 下 autosave 周期落盘不触发** | 位置类改动无法用文件验证 | 位置真值归真机；用拓扑/undo/redo 代替 |
| **WSL 的 IP 每次重启会变** | 探针连不上 ⇒ 误判「OSC 没开」 | 每次现取 `hostname -I` |
