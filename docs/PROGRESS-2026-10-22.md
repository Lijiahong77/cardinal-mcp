## 3. 新增能力速查（现在能做什么）

```text
/module-add   "sii"  <plugin|model slug>  <x格>  <y格>   → 新模块 id（可 undo）
/load-skipped ""                               → 上次 load 跳过的模块/线清单
/log-get      "ii"   <from>  <limit≤64>       → 进程内日志增量读
/cables-page  "ii"   <offset> <limit≤64>      → 分页读线
/module-copy  "hi"   <moduleId> <withCables>  → 复制模块
```

MCP 侧对应：`cardinal_add_module` / `cardinal_load_skipped` / `cardinal_log_get` / `cardinal_cables_page` / `cardinal_module_copy` / `cardinal_add_cable` / `cardinal_remove_cable` / `cardinal_move_module` / `cardinal_remove_module`。

```bash

#    ⇒ 期望：端点数 33 / 33，✅ 校验通过

#    只动 src/ 层          ：cd src && make -C CardinalNative -j12
#    动 Rack 层（src/Rack/）：cd src && make rack.a -j12 && make -C CardinalNative -j12
#    动 plugins/ 层        ：cd plugins && make plugins.a -j12 && cd ../src && make -C CardinalNative -j12
#    （Rack 头文件动过 ⇒ plugins 全量重编 30-60 分钟，见 §6）

#    OSC 端口 2228 自动开；MCP 侧用 CARDINAL_IP=<WSL IP> 连
```

## 6. 已知坑速查（这轮踩的，别再踩）

| 坑 | 症状 | 正解 |
|---|---|---|
| 🔴 **截图读到的是空缓冲（不是「截旧帧」）** | `/screenshot` 出的 PNG **全黑**（3103×1899 里只有 3 个非零字节）；两次截图 MD5 相同**只是因为两张都是全黑** | **NanoVG 是延迟渲染器**：`scene->draw()` 只记录命令，真正 rasterize 在 `nvgEndFrame()`，而 DPF 在 `onNanoDisplay()` **返回之后**才调它 ⇒ 回调内任何缓冲都没有画面。且 FBO 绑定时 `glReadBuffer(GL_FRONT/GL_BACK)` 是 `GL_INVALID_OPERATION`，`glReadPixels` 什么都不写。**正解 = 延后一帧读 GL_FRONT**（上一帧此时已 rasterize+swap）。见 `src/override/Window.cpp` 截图段 |
| **采样路径存相对路径 = 加载静默失败** | demo 打开后 sampler 面板全 empty，但文件里明明写着 `samples/kick.wav` | samplerx8 走 `AudioFile::load()` 的 `std::ifstream file(filePath)`，**按进程 cwd 解析**；exe 从 `win64/` 启动 ⇒ 相对路径解析到 `win64/samples/`。`samples_root_dir` **只用于文件对话框记住目录，不参与加载** ⇒ 必须存**绝对路径** |
| **为加新控件搬动既有控件坐标** | 李截图抓出：STEP/LAYER/EDIT 与 SVG 底座错位（偏左 4/5/6mm） | **改布局前先读 SVG artwork 对设计意图**；新控件放空隙不搬旧的——BARS 最终入 EDIT(112)→TRK1(140) 的 28mm 空隙中央（126），并在 SVG 补同款双圆底座 |
| **MiniArranger 的 measures 旋钮是绝对值语义** | 按归一化发 0.467 ⇒ 被写回逻辑 `round(0.467)→0→clamp→1` 写成 **1 小节** | `configParam(1.f,16.f,4.f)` 存的就是小节数本身（非 0..1）；OSC set 直接发 8，不是 0.467 |
| **Cardinal 上游禁用了 autosave**（`CardinalCommon.cpp:3063` `autosaveInterval=0`） | `save_live` 永远读到上次 `/load` 的内容，验不了 OSC set param 的效果 | autosave 只在 `/load` 时刷新（blob 解压进 autosave 目录后 `loadAutosave()`）；**存盘验证走李的 GUI Save As + 读文件** |
| **系统模板是 V1 JSON，V2 加载器读不了** | 启动弹 "Could not load system template patch" 模态框 ⇒ 阻塞消息泵 ⇒ OSC 的 120 帧延后启动永远走不到（自启进程全灭） | 已修：用户模板 `Documents/Cardinal/templates/native.vcv` 放有效 V2 + 系统模板也换成 V2；原 V1 备份 `tmp/native_template_json_backup.vcv`。**弹窗类阻塞会让整个 OSC 验收链假死** |
| **Cardinal 编译的是 `src/override/Engine.cpp`**，不是 Rack 原版 | 链接期 `undefined reference to rack::xxx` | 改 Rack 层前先 `ls src/override/`；判定：`nm -C src/rack.a \| grep 符号` |
| **typespec 必须与参数顺序一致** | 端点永远哑（liblo 不派发） | `"sii"` ≠ `"ssi"`；写完立刻用探针发一条真消息验 |
| **别在 OSC 侧调人类路径独有的 UI 动作** | 调 `loadTemplate()` 后 undo 就让 OSC 失联 | 手动执行只抄「引擎 + 容器 + 定位」三步 |
| **错误码语义别复用** | `err:E_NO_PLUGIN` 在既有约定里是「桥未就绪」 | 「slug 不存在」用 `err:E_NO_MODEL` |
| **探针自己的回包语义** | 同一份探针里 ask 返回列表还是元组？ | 先 dump 原始回包对齐语义，再写断言 |
| **自写 OSC 消息别手拼** | 地址段多一个 `\0` ⇒ 请求发不出去 | 照抄已验证的构造器（pad 到 4 字节） |
| **WINE 下 autosave 周期落盘不触发** | 位置类改动无法用文件验证 | 位置真值归真机；用拓扑/undo/redo 代替 |
| **WSL 的 IP 每次重启会变** | 探针连不上 ⇒ 误判「OSC 没开」 | 每次现取 `hostname -I` |
| **改 `plugins/` 层 ⇒ 必须先重编 plugins.a** | 只编 CardinalNative 会链接到旧插件库 | `src/Makefile.cardinal.mk:117` `RACK_EXTRA_LIBS=../../plugins/plugins$(TARGET_SUFFIX).a` ⇒ 先 `make -C plugins plugins.a` 再 `make -C src/CardinalNative` |
| **Rack 头文件改了 ⇒ plugins 全量重编** | 1600 个文件重编（30-60 分钟） | 判据 = `make -d` 看 "Prerequisite ... is newer than target"；根因是 `.d` 依赖文件比 `.o` 新 |
| **`logger.hpp` 加了 `std::vector` 却没 `#include <vector>`** | plugins 全量重编时 `error: 'vector' in namespace 'std' does not name a template type` | C3 批只编了 `rack.a`+CardinalNative、没编 plugins ⇒ 这个 bug 一直没暴露。**任何 Rack 头文件改动后必须编一次 plugins** |
| **`git apply` 的 hunk 行数声明必须精确** | `error: patch fragment without header at line N` | 手改 patch 时数清 context+新增的实际行数（`@@ -a,b +c,d @@` 的 b/d 是**新**侧行数） |
| **改 C++ 源码先备份再改** | 改错了无法回退 | `cp X.cpp X.cpp.bak-<批名>`；改完用 diff 生成 patch 段 |
